# 人工评测记录（模板）

`eval/run.py` 只能自动评**系统侧**指标，包括规则化的五维评分、硬约束违规、关键需求项识别准确率和系统一次通过率。下面这些指标需要真人参与，无法由脚本生成，所以只提供模板，**不预填任何数字**：

| 指标 | 计算方式 | 用哪张表 |
| --- | --- | --- |
| 方案初稿制作时间 | 同一询单的「纯人工制作耗时」对比「AI 起草 + 顾问修改耗时」，取中位数 | 方案人工评测记录表 |
| 顾问审核一次通过率 | 「顾问审核一次通过 = 是」的条数 ÷ 总条数 | 方案人工评测记录表 |
| 人工五维评分 | 每维 1–5 分，取均值；与 `eval/report.md` 的自动评分对照，校准评分口径 | 方案人工评测记录表 |
| 知识库抽样回答准确率 | 「是」= 1、「部分」= 0.5、「否」= 0，求和后 ÷ 抽样数 | 知识库抽样问答记录表 |
| 资料查询耗时 | 人工查询对比 AI 查询，取中位数 | 知识库抽样问答记录表 |

填写要求：

- 「询单来源」必须如实填写「真实脱敏」或「构造」，两类在报告里分开统计；
- 每次抽检都写清抽检人和日期，保证结果可以复核；
- Bad Case 归因用三类：知识缺失、检索偏差、行程冲突，和 `eval/run.py` 的自动归因保持一致。
