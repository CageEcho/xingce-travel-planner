## 1. 竞争地图

~~~
                         面向顾问 / 供给侧 (B)
                                   ↑
    ┌──────────────────────────────┼──────────────────────────────┐
    │  B 端定制师工作台 SaaS        │        【行策】               │
    │  路书云 TOS / 超级定制师      │   事实可核验的方案生成         │
    │  小强 OTAS                   │   三道防线 + 三态校验          │
    │  → 提效但不校验事实           │   → 敢对客交付                │
不承诺 ├──────────────────────────────┼──────────────────────────────┤ 承诺
事实   │  通用 AI 行程规划            │        OTA 的 AI 助手         │ 事实
准确   │  Mindtrip / Layla /          │  携程问道+TripGenie           │ 可核验
    │  Wonderplan / Wanderlog      │  飞猪问一问→飞猪帮帮           │
    │  → 生成即交付，错了用户自担    │  → 有真实库存，但服务标品      │

                         面向旅行者 / 需求侧 (C)

**四类玩家，只有第四象限是空的**——而那正是高端定制的战场。

## 2. 赛道一 · 通用 AI 行程规划工具（C 端）

代表：**Mindtrip、Layla、Wonderplan、Wanderlog、Google 搜索 AI Mode Canvas**

### 2.1 2026 年的格局变化 📊

| 事件 | 影响 |
| --- | --- |
| Mindtrip 2026-05-06 上线聊天内机票预订（经 Sabre + PayPal） | 从「规划工具」跨进「交易闭环」 |
| Layla 通过 Skyscanner 订票，**被 Expedia 整体收购** | AI 规划入口正在被 OTA 巨头收编 |
| Google 在搜索 AI Mode 推出 Canvas 逐日行程 | 规划能力正在成为搜索的免费附属功能 |
| Wanderlog 把无限 AI 放进 Pro，免费版设额度 | 单纯的「生成行程」已不值钱 |

来源：[aitravel.tools · Best AI Trip Planners 2026](https://aitravel.tools/best-ai-trip-planner/)、[Voyaige · Best AI Travel Planner 2026](https://voyaige.to/blog/best-ai-travel-planner-2026)、[MonkeyTravel · Mindtrip Review 2026](https://monkeytravel.app/blog/mindtrip-review-2026)

> 💡 **对我们最重要的一条**：**「生成一份行程」这件事正在归零**——Google 免费送，Wanderlog 当引流。这反过来证明了一件事：**价值不在生成，在于生成的东西敢不敢用**。

### 2.2 能力观察 🔍

| 维度 | 表现 | 来源 |
| --- | --- | --- |
| **事实准确性** | 第三方评测明确指出：**无实时数据连接的工具（Wonderplan、iPlan.ai）在营业时间、价格、可订状态上幻觉风险更高，出行前务必核实** | [aitravel.tools](https://aitravel.tools/best-ai-trip-planner/) |
| 追问策略 | Layla **不立刻出方案，先确认参数并追问澄清**——更贴需求但牺牲出稿速度 | [MonkeyTravel](https://monkeytravel.app/blog/best-ai-trip-planners-2026-compared) |
| 家庭场景 | Mindtrip 能记住孩子年龄并推荐儿童友好站点；Layla 会主动提醒「晚点到达对 7 岁孩子可能太累」 | [MonkeyTravel](https://monkeytravel.app/blog/best-ai-trip-planners-2026-compared) |
| 协作 | Mindtrip 支持共享行程、群聊、照片导入、收据整理，但**界面想做的事太多，偶尔杂乱** | [MonkeyTravel](https://monkeytravel.app/blog/mindtrip-review-2026) |
| 商业模式 | Mindtrip 免费、靠预订分成；Layla 免费版可用，实时价格与 PriceLock 为付费项 | 同上 |

### 2.3 对本项目的启示

| # | 启示 | 我们怎么做 |
| --- | --- | --- |
| 1 | **「先追问再出稿」已被验证是对的**，Layla 走了同一条路 | 我们走得更远：必问项缺失**直接阻塞生成**，不是「问一下就算了」 |
| 2 | 家庭场景的儿童适配是共同难点，但他们靠 prompt 记住年龄 | 我们把儿童年龄做成**硬约束 H1**，房型住不下直接拦截并重排 |
| 3 | 幻觉风险被评测公开点名 | 这正是三道防线的存在理由 |
| 4 | 交易闭环是他们的终局 | 我们**明确不做预订**——不跟 OTA 抢交易 |

> **关键差异**：它们做的是「旅行者自己用」，错了旅行者自己承担。我们做的是「顾问拿去对客」，错了顾问要赔钱和商誉。**责任归属不同，产品的正确性标准就不同**——这不是能力差距，是设计目标差距。

## 3. 赛道二 · OTA 的 AI 助手（最强的一类）

代表：**携程「问道」+ TripGenie、飞猪「问一问」→「飞猪帮帮」**

### 3.1 携程：垂直大模型 + 可靠答案库 📊

| 项 | 内容 |
| --- | --- |
| 「携程问道」 | 2023-07 发布，行业首个旅游垂直大模型；筛选自 200 亿高质量非结构化旅游数据 + 携程结构化实时数据训练 |
| **可靠性做法** | 推出旅游业「**可靠答案库**」，在算法基础上**加入人工校验**，并以口碑榜/热点榜/特价榜体现在答案中 |
| TripGenie（Trip.com） | 个性化推荐 + 完整行程 + 站内预订；支持 12 种语言；结构化行程可存入「我的行程」续做 |
| 效果数据 | 2024 财年流量 +200%、浏览时长 +100%、对话量 +200%；机票问题自助解决率 78%、酒店 68%；**使用 TripGenie 的订单转化率较普通用户高 1 倍** |
| 商家侧 | 内容生产从 8.5 分钟缩至 15 秒、合格率 98.9%+；营销素材 30 分钟→3 分钟 |

来源：[界面新闻](https://www.jiemian.com/article/9761673.html)、[甲子光年](https://www.jazzyear.com/article_info.html?id=1053)、[电商派 · TripGenie](https://www.pai.com.cn/223588.html)、[Vocust · 携程 AI 战略](https://www.vocust.com/school/insightcase/364.html)

**🔍 第三方点出的短板**：携程问道仍停留在聊天框形态，需先点搜索栏再进「旅行 AI」入口，**路径繁琐**；回答常从携程榜单出发给出**标准路线，个性化调整能力有待改进**（[搜狐实测](https://www.sohu.com/a/902524701_100661)）。

### 3.2 飞猪：Multi-Agent 路线 📊

| 项 | 内容 |
| --- | --- |
| 「问一问」 | 2025-04 上线，**多智能体架构**：行程助手、路线定制师、智慧交通顾问、酒店顾问、攻略达人、本地导游、**预算管理师**、服务保障专员 |
| 任务流 | 行程助手拆解任务 → 唤起各 Agent 分头调用**真实机酒报价与景点数据** → 预算管理师汇总核算 → 输出含可预订商品卡的方案 |
| 「飞猪帮帮」 | 2026-08 杭州发布；**去聊天框化**，智能面板嵌入首页、搜索栏、行程页、订单页与各频道 |
| 效果数据 | 交付结果**可用率评分较上一代提升超 70%**，可比任务平均耗时减少近 10%；3 个月核心开发周期上线 148 个复杂需求，**AI 生成代码占比超 85%** |
| 战略判断 | 飞猪 CEO 2024 年即提出：未来可能没有 OTA，而是 Omni-intelligence Travel Agents |

来源：[执惠 · 飞猪问一问](https://www.tripvivid.com/45382.html)、[南方都市报 · 飞猪帮帮](https://m.mp.oeeee.com/a/BAAFRD0000202608121642324.html)、[掘金 · 三大 OTA 的 AI Agent](https://juejin.cn/post/7676253300934066217)

### 3.3 为什么这是最强的一类，却仍然不覆盖我们

| 他们的优势 | 我们无法比 | 但是 |
| --- | --- | --- |
| 真实机酒库存与实时报价 | ✅ 完全比不了 | 所以我们**明确不做库存查询**，定位是方案生成 |
| 海量结构化供给数据 | ✅ 比不了 | 但高端定制用的是**协议价与私域资源**，不在 OTA 库里 |
| 流量与转化闭环 | ✅ 比不了 | 我们不碰交易 |
| **面向旅行者** | —— | ⚠️ **这正是缺口**：他们优化的是「让用户自己下单」，不是「让顾问出一份敢签字的方案」 |

**三个结构性错位**：

1. **净价与协议价进不了 OTA 的 AI**。顾问的核心竞争力恰恰是「我拿到的价格和你在携程上看到的不一样」，这部分数据 OTA 不会有，也不该有。
2. **OTA 的目标函数是转化，不是准确**。转化率高 1 倍是好事，但它优化的是「用户愿意下单」；顾问要的是「这条不会出事」。目标函数不同，产品形态就不会收敛到同一点。
3. **多 Agent ≠ 事实可核验**。飞猪的「预算管理师」调的是平台真实报价，这很强；但高端定制的报价来自线下协议与临时询价，**没有 API 可调**——这正是行业公开承认的卡点（见 §4.2）。

> 💭 **推断但有把握**：OTA 会持续吃掉「标品定制」，而「高端非标」的瓶颈不在模型也不在流量，在**私域供给数据的结构化**。这件事谁也帮不了顾问，只能自己做——这就是护城河的位置。

## 4. 赛道三 · B 端定制师工作台 SaaS（最直接的对标）

代表：**路书云 TOS、超级定制师（zouke.com）、小强 ERP / OTAS**

### 4.1 路书：行业里最典型的定制师工作台 📊

| 项 | 内容 |
| --- | --- |
| 定位 | 定制游企业一站式解决方案，SaaS 产品「路书云定制旅行工作台」 |
| 核心功能 | 辅助定制师**快速编辑行程、积累线路方案、创建机构定制经验知识库** |
| 用户 | 旅行社/定制机构的计调、产品经理、定制师；也被自驾、滑雪、潜水俱乐部和旅拍公司使用 |
| 产品思路 | 不提供简单模板，把目的地信息与玩法**模块化**，用智能交通把点串成线，覆盖**全球 400 万 POI**，鼓励机构搭建专属线路库/POI 库/素材库 |
| 历史 | 2014 年创立，短暂试水 C 端后转向 B 端，2016 年底完成千万元级 A 轮 |

来源：[环球旅讯 · 路书 A 轮](https://m.traveldaily.cn/article/113283)、[环球旅讯 · 这家公司做起了技术服务](https://m.traveldaily.cn/article/109702)、[路书官网](https://www.lushu.com/)

### 4.2 路书暴露的卡点，正好是我们的切入点 📊

公开报道里有两条关键信息：

> **① 报价断点**：路书客户反映，**并非每个 POI 都有完整价格信息，行程报价时定制师还必须自行上 OTA 查询产品信息并录入**；一些小众 POI 没有预订渠道和产品。
> **② 官方口径**：路书方面解释，云 TOS 是「**80% 人工 + 20% 智能**」的行程规划系统，认为**定制的边界目前仍然是人**。
> ——[环球旅讯](https://m.traveldaily.cn/article/113283)

**这两条信息的价值极高**：

| 观察 | 含义 | 行策的对应设计 |
| --- | --- | --- |
| 价格要定制师手工去 OTA 查并录入 | **工具管了「编排」，没管「事实与价格」** | 价格由**规则引擎从自有价格档算**，模型不碰金额；缺价格档 → 判 UNKNOWN 进待核实清单 |
| 「80% 人工 + 20% 智能」 | 智能占比低，主要是编辑器不是生成器 | 我们把编排交给模型，但**用三道防线兜住事实** |
| 「定制的边界目前仍然是人」 | 行业共识：人不可替代 | ✅ **我们完全同意**——所以设计了 4 个人工确认卡点，不追求全自动 |

> 💡 **这不是反驳，是分工**：路书证明了「顾问需要工作台」这个需求真实存在且有人付费。我们和它的差别不在「谁更智能」，在于**我们把「这条行程对不对」变成了可自动校验的问题**，而它把这件事留给了人。

### 4.3 能力差异

| 维度 | 路书云 TOS 类 | 行策 |
| --- | --- | --- |
| 行程编辑 | ✅ 强（模块化、400 万 POI） | ⚠️ 弱（M2 才做编辑，M0 只有生成） |
| 线路知识库沉淀 | ✅ | ⚠️ 资源库有，线路模板未做 |
| **自然语言需求采集** | ❌ 表单/手工 | ✅ 原话 → 需求卡，必问项强制确认 |
| **硬约束自动校验** | ❌ | ✅ H1–H11 三态判定 |
| **防幻觉架构** | 不适用（不生成） | ✅ 三道防线 |
| **自动成本核算** | ⚠️ 需手工录价 | ✅ 规则引擎，缺价显式标注 |
| 订单/采购/结算 | ✅（ERP 类产品） | ❌ 明确不做 |

**结论**：路书是**编辑器**，行策是**生成器 + 校验器**。二者在产品形态上甚至可以共存——💭 长期看，行策的输出接入这类 ERP 的订单流是自然的演进。

## 5. 赛道四 · 自营定制旅行社（他们是客户，不是对手）

代表：**6 人游、无二之旅、赞那度、指南猫/世界邦（达人平台）**

### 5.1 公开数据佐证了我们的痛点假设 📊

| 数据 | 来源 | 对应我们的假设 |
| --- | --- | --- |
| 6 人游**平均每单 7 万元**，每单 4~5 人；**80%+ 订单为一对一小团定制** | [环球旅讯](https://m.traveldaily.cn/article/75127) | 高客单 → 效率提升的绝对收益可观（[立项 §3](02-立项报告.md)） |
| **一份出游方案经反复沟通、修改、敲定，至少历时三四天** | [澎湃新闻](https://www.thepaper.cn/newsDetail_forward_12047403) | ✅ 佐证痛点 P1/P7 |
| 某些高端机构**单订单平均沟通时长超 30 小时** | [搜狐 · 2026 高端定制旅行社盘点](https://m.sohu.com/a/1005897856_122556950/) | ✅ 我们假设的 8 小时/方案属保守 |
| 有从业者称平台定制需求单**成单率最高约 10%**，「骗攻略的占一半以上」 | [知乎 · 许义对话 6 人游贾建强](https://zhuanlan.zhihu.com/p/510570335) | ⚠️ **大量方案工时是沉没成本**——这一条我们之前没考虑到 |
| 6 人游国内定制团利润率约 5%、出境约十几个百分点 | [界面新闻](https://www.jiemian.com/article/1529115.html) | 服务费率 8% 的默认配置量级合理 |
| 无二之旅 C 端业务**约 50% 借助 POI 数据库与机器算法完成** | [人人都是产品经理](https://www.woshipm.com/evaluating/665792.html) | 自动化占比有天花板，与「人工卡点」设计一致 |

### 5.2 一条必须正视的行业反思 📊

6 人游创始人贾建强的原话大意：

> 很多定制师没去过目的地，靠攻略和公司培训完成基础了解，再拿着当季主推的 **3 条线路问题清单**上线接单。原因正是效率——如果每个需求都去理解并执行，时间成本和操作成本都很高，所以一般做法是**把相同目的地的各种需求最终都转化成既有的 3 条线路**，只有这样效率才高。
> ——[知乎 · 许义对话贾建强](https://zhuanlan.zhihu.com/p/510570335)

**这是对「定制游」最狠的一句批评，也是本项目最该回答的问题**：

| 问题 | 行策的回答 |
| --- | --- |
| 效率压力会把「定制」退化成「3 条线路的销售」 | 我们降低的正是**理解与编排的边际成本**——如果出一份真正按需的方案只要 2.5 小时而不是 8 小时，顾问就没有必要把所有需求都往 3 条线路上塞 |
| 定制师利益结构导致推荐「公司最挣钱的」而非「用户需要的」 | **商业优先级权重上限锁死 0.10**，且写在配置校验器里、超过直接启动失败——这是**用架构约束商业冲动** |
| 系统只能解决订单流转，核心还是人反复修正 | 承认。所以 M2 的**锁定 + 增量重排**是决定长期采纳率的功能，不是锦上添花 |

> 💡 这一节是整份竞品分析里最有价值的部分：**竞品的失败反思，比竞品的功能列表更有信息量**。功能可以抄，教训只能借。

## 7. 差异化定位

**一句话**：别人做「生成一份看起来不错的行程」，我们做「生成一份**敢发给付了 30 万的客户**的行程」。

三件别人不做、我们必须做的事：

| # | 我们做 | 别人不做的原因 | 我们付出的代价 |
| --- | --- | --- | --- |
| 1 | **模型只输出 ID，事实全部回填比对** | C 端不要求；B 端工具干脆不生成 | 生成灵活度下降 |
| 2 | **三态校验，缺数据显式暴露为 UNKNOWN** | 会让产品显得「不够智能」 | 待核实项影响观感 |
| 3 | **必问项不得静默假设，缺失即阻塞** | 多问一轮降低转化 | 采集链路更长 |

> 这三条都在**主动牺牲「看起来聪明」来换「可以负责」**。对 C 端是减分项，对顾问是唯一的入场券。

### 7.1 护城河在哪

| 候选 | 是否成立 | 理由 |
| --- | --- | --- |
| 模型能力 | ❌ | 谁都能调同样的模型 |
| 行程编辑体验 | ❌ | 路书做了十年，比不过 |
| 流量 | ❌ | OTA 的主场 |
| **私域供给数据的结构化** | ✅ | 协议价、私域资源、顾问经验，OTA 拿不到，模型学不会 |
| **约束规则库** | ✅ | H1–H11 只是开始；每个 Badcase 都沉淀为一条规则 + 一条回归用例 |
| **「敢对客」的架构信誉** | ✅ | 一旦顾问信任「这套系统不会编」，迁移成本极高 |

## 8. 竞争风险

| # | 风险 | 可能性 | 判断与应对 |
| --- | --- | --- | --- |
| 1 | 通用 AI 工具补上约束校验 | 💭 中期可能 | 它们缺的不是技术是**结构化供给数据**，而这是运营苦活 |
| 2 | **OTA 把 AI 能力开放给合作商** | 💭 较可能（飞猪已在做全链路嵌入） | 差异化要落在「不绑定单一供给」与「协议价隔离」 |
| 3 | **路书类工具加上生成与校验** | 💭 **最直接的威胁** | 它们有客户、有 POI 库；我们的时间窗在于它们当前口径是「定制的边界仍然是人」 |
| 4 | 头部定制社自建系统 | 💭 会发生 | 腰部机构不会自建，那是目标客户 |
| 5 | 模型进步让「防线」显得多余 | ❌ 不会 | 防线防的是**模型不知道你库里有什么**——信息边界不是能力边界 |

第 3 条要特别说：**路书是最像我们的产品，也最可能成为竞争对手**。但它当前的产品哲学是「工具辅助人编排」，我们是「系统生成 + 系统校验 + 人确认」。这两种哲学会导向不同的架构，**不是加个功能就能转向的**。

## 9. 关键结论

1. **空位确实存在**：四类玩家里，没有一类同时满足「面向顾问 + 承诺事实可核验」。
2. **最强的对手是 OTA 的 AI，但它和我们的目标函数不同**（转化 vs 正确），且拿不到协议价与私域资源。
3. **最像的对手是路书这类 B 端工作台，它自己承认报价要手工录、智能只占 20%**——这恰好是我们的切入点。
4. **自营定制社是客户不是对手**，且他们公开的痛点数据（30 小时/单、成单率 10%、3 条线路化）**验证了本项目的立项前提**，也提出了我们之前没考虑的「沉没工时」问题。
5. **「生成行程」正在归零**（Google 免费送），**价值只能建立在「敢用」上**——这进一步强化了三道防线与三态校验的战略地位。
